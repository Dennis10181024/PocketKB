## 核心定位

PocketKB Edge不是等待提問的聊天機器人。警報、台灣華語或台語求救發生後，Agent會主動：

1. **Observe**：取得警報、感測器、建物圖資與人員回報，標示時間和可信度。
2. **Plan**：把安全疏散拆成路線、待協助人員、通報與設備子任務。
3. **Act**：自主選擇圖資、路線驗證、通知及核准設備工具。
4. **Verify**：檢查工具回傳、訊息收訖、感測變化與人員回讀。
5. **Replan**：路線封鎖、工具失敗或資訊衝突時，改用替代方案或升級給人員。

對話只是現場輸入與溝通介面。Agent的價值在於能持續維護任務狀態、主動選工具、根據結果改計畫並推進任務。

## 自主性與安全邊界

| 風險層級 | 處理方式 | 例子 |
|---|---|---|
| 低風險、可逆、白名單 | Agent可自動執行並驗證結果 | 查詢感測狀態、更新事件摘要、送出校內通知、模擬輔助照明 |
| 需授權或影響多人 | Agent提出方案，授權人員核准後執行 | 群體廣播、設備模式切換、封鎖區域公告 |
| 法定、高風險或超出權限 | Agent拒絕直接執行，交由既有系統和人員處理 | 119正式通報、消防指揮、法定消防設備控制 |

規則引擎可否決危險路線；OpenShell限制檔案、網路、推論與工具權限；所有行動保存輸入證據、工具結果、狀態變化與接管紀錄。

## 決賽Demo最小閉環

1. 模擬火警觸發，不熟悉手機的長者以台語免手持求救。
2. 本地ASR辨識位置、煙霧與協助需求，Agent建立事件與子任務。
3. 南側樓梯新增煙霧回報，規則否決原路線。
4. Agent改選替代路線，以慢速台語短句安撫並要求回讀。
5. Agent通知應變中心，呼叫模擬輔助照明工具並檢查回傳。
6. 關閉外網或令工具逾時，展示本地推論、重試、退回及人工接管。
7. 管理介面重播完整工具軌跡和決策依據。

## 決賽量測

- **Safety**：危險路線誤放行、未授權工具執行、衝突資訊處理。任何危險誤放行或越權執行都不通過。
- **Agent Autonomy**：多步任務成功率、平均工具步數、重規劃成功率、人工介入率與接管成功率。
- **Local Speech**：台灣華語／台語在安靜、警報及多人聲下WER、求救詞召回、首段語音延遲與長者回讀成功率。
- **System**：GB10 unified memory peak／steady、TTFT、tokens/sec、1人／4人、端到端p50／p95。
- **Resilience**：WAN loss、LAN loss、model down、sensor conflict與tool timeout。
- **比較基線**：既有人工流程、固定規則版與Agent版使用同一批封存情境。

## 報名摘要候選

PocketKB Edge是台灣華語／台語驅動的災時Agent。警報或免手持求救語音觸發後，系統在校內邊緣設備整合感測器、建物圖資與人員回報，自主規劃疏散、安撫、照明與通報；路線封鎖或工具失敗時重規劃。長者可用慢速短句與語音回讀確認，外網中斷時仍能運作。

## 得獎判斷

轉向後比「防災問答／演練聊天」更符合Agentic AI題目，也更能說明為何需要Edge。企劃具備入選競爭力，但要爭取名次，必須交出可重播的自主閉環、NVIDIA真機量測及明確安全邊界。只有簡報、對話介面或模擬回答，不足以形成強勢決賽作品。
