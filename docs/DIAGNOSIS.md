# PocketKB 災前情境演練現版診斷

基準為提交 `a2c43d2`。測試以一般大眾與大學生的日常補充演練為目標，涵蓋六個劇本及三種角色。逐次輸入、回覆、意圖標註、狀態與計時見 [原始紀錄](DIAGNOSIS_RUNS.json)。

## 測試方法

- 每個劇本各開三個新場次。認真新手走完整路線，口語角色用改寫及離題輸入，一直問問題的角色在各階段提出不同問題後再做決策。每輪走到終局並讀取回顧，另做危險、資源不足、提問與故障探針。
- 規則判讀在既有 JavaScript 引擎執行。Chrome 另用現有線上畫面重播相同回合，測試工具把回合請求接到本地規則引擎。線上阻擋和故障探針則使用現有 HTTP 後端與瀏覽器。上游故障由測試替身注入。
- 耗時為自動操作從點開始到取得終局回顧的實測分鐘。它包含網頁操作與渲染，無真人閱讀、打字與思考時間，也無真實模型等待。
- 自由輸入以事先標註的預期判讀計分。動作須觸發行動事件，非行動須維持原狀，純問題須分類為詢問且維持原狀。此數值衡量分類及是否執行，問題有沒有被回答另外分析。測試包含用詞接近既有選項的正常流程，數值僅適用這批輸入。
- 改用選項次數以同義改寫卡住後，為了繼續而改送現有引導選項原文的次數計算。現版線上頁沒有引導行動按鈕，本次在 Chrome 將選項原文填入文字欄位。實際點選 UI 的次數為 0。學校地震口語輪在改用選項前已被鎖定。

## 與必要原則的差距

- **結果與敘事**。程式碼中狀態由引擎更新，GPT 敘事欄位仍是自由文字。後端檢查長度及來源 ID，無法由此驗證敘事是否與已確認結果一致。
- **來源**。劇本有來源清單，火災有節點級來源 ID，v3 尚缺逐行動與後果的依據對應。以淹水為例，來源為教育部網站入口，電源判定缺少可直接對照的資料段落。這是現版資料結構檢查，逐條官方內容的專業核對仍待執行。
- **模型設定及預算**。後端可由環境變數選模型，但有寫死的預設。後端目前以程序共用請求上限與場次回合上限控制，缺每場模型呼叫與費用上限。

### 真實 GPT 模式

**0 次真實 API 呼叫，回覆、狀態與延遲均無測值。** 執行環境沒有 `OPENAI_API_KEY`，既有本機後端也未取得健康回應。Chrome 測試中的替身僅用於確認降級。現版每筆完整回合呼叫理解與敘事兩次，六個劇本各 10 筆至少需要 120 次，100 次上限最多能跑 50 筆完整回合。現有證據只可確定本輪沒有呼叫 GPT。取得真實結果後應逐筆查呼叫階段與 `fallbackReason`，模型兩階段均完成且回覆通過驗證時，才能評估敘事提示是否造成模板化。

## 步驟 0.5 · 修正清單

1. 規則引擎在動作匹配前辨識已涵蓋的想像、假設、否定及詢問。假設使用劇本既有危險資訊說明可能後果，詢問回引原話並提示已知線索或追問。這些回合原狀保留。
2. 通用 v3 引擎在正式執行前驗證現場事實與資源。淹水關電三項條件缺一時記為危險選擇，關電不執行。現有劇本開頭明示三項皆成立，缺漏和不安全變體以測試注入。 [CDC 電氣風險指引](https://www.cdc.gov/natural-disasters/response/what-to-do-protect-yourself-from-electrical-hazards.html)
3. 伺服器將兩階段 GPT 共用 8 秒期限，失敗或逾時後從最後確認狀態提交同一筆規則結果，重送同請求 ID 回傳既有結果。瀏覽器與 Android 遇傳輸錯誤，從最後確認狀態轉為本機判讀，該場後續保持本機。介面顯示「目前使用離線判讀」。遠端若在斷線前已收到請求，可能保有孤立的伺服器場次，客戶端不再採用該場次。
