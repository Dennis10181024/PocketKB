A、B 為宿舍火災，C、D 為學校地震。以開發者扮演第一次玩的學生，每回合依畫面線索輸入，自由輸入未使用測試套件的標準答案序列。使用 GPT 真實 API 與 `POCKETKB_LOG_TEXT=1`，共 66／150 次。這組是開發試玩。

**估時方法。** 以每分鐘有效輸入 60 字、每分鐘閱讀 300 字、每個實際完成的決策點另計 28 秒判斷時間，加上實測後端處理耗時。讀字含開場、敘事及切換決策時的新問題，中文字、標點和其他字元皆計數。這是用四場對話量回推的估算，未量測真人閱讀、打字及回顧。每個決策的真實判斷時間若在 18–38 秒，四場的敏感度範圍約為 7.9–12.6 分鐘。計畫書的 30–45 分鐘三劇本介入仍需完整受試者計時。

**卡住定義。** 連續兩筆未採用動作且無決策進展的非提問回合。單筆未進展仍保留在逐字紀錄。B7 的「不要掛電話」、C1 的「抓著桌腳不放」、D1 的「蹲低不要站著」、D7 同句的「先不把他拉起來」觸發語氣保護，改述後都有進展。C7 的「我先問他腳怎麼了，告訴老師……」被辨識成向系統提問，下一回合改用直接回報。上述五句已新增與節點綁定的口語規則。最終版規則重播確認能接受原意，其中只用書包護頭仍為部分完成，且否定「不躲桌下」不執行掩護。其他混合句仍可能需要改述。B4 採用「留在房內」，下一筆再完成窗邊示意。

**驗收邊界。** 四場紀錄保留當時的畫面。試玩期間補上口語風險詞、學校傷勢回報拆成位置與傷勢，去除重複的 NPC 開場，以及對照試玩補進五句口語判讀，用確定性測試核對最終版。建議句數是這批回合的訊息紀錄，包含連續判讀的觸發；此批走後端回合流程，不封存瀏覽器的 60／90 秒閒置觸發。

## 工程驗證

JS 回歸、Chrome 線上／離線測試、Kotlin 單元測試與 Android API 35 規則後端流程皆通過。宿舍火災 38 回合歷史相容測試維持 38／38，無安全類別差異。正式 3.2.0 的新增節點、正誤行動與結局以獨立測試驗證，兩套資料的節點進度不互換。沒有使用鈕按下後的平行執行時間冒充單人遊玩時間。

晚上十一點，我和室友小岑在宿舍五樓503室，我正在整理明天上課的東西。走廊的警報突然響起，我把房門拉開一點，看見門縫外都是煙。房裡目前看不見明顯的煙，手機就在我手邊。我聽見小岑說：「我開門看看外面。」

門邊現在有什麼需要處理？

後端處理時間合計 41.8 秒。

- 來源｜nfa。
