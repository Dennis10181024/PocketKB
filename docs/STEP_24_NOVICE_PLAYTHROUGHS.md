| A | 13 | 安全待救獲救、無傷 | 0 | 2 | 1 |
| B | 10 | 安全待救獲救、無傷 | 0 | 0 | 0 |

- 前 30 回合：理解退回 **3/30**，均為 `MODEL_PROTECTED_LANGUAGE`（A5、C2、C9），即模型動作提議未通過語氣安全驗證。獨立的敘事模板回退 **3/30**，均為 `NARRATION_VALIDATION`（A3、C3、C5）。理解逾時 0、API 逾時 0。全 36 回合另有 A12 的一次語氣安全驗證回退，合計 **4/36**。實際 API 共 **56 次**。
- 「狀態完全不變」表示節點與時間都沒動，也沒有新增狀態機事件。若只看節點，三場都曾在同一點停留數輪。A2、A3 因門未關連續攔截，畫面分別交代毛巾貼不住、無法隔煙的原因。A4 接住遮住口鼻的動作並說明限制，A6 關門進入通報。B4、C1 等提問的狀態刻意不變。
- 本次實跑經過線上教練與實際 API，未經測試替身。表中的「退回」由 `fallbackReason` 判定。沒有以本次跑在同機的教練流程估算手機網路斷線率。研究欄位存入生成日期目錄中的獨立場次 JSONL，原句為本次受控開發測試輸入。
- 真實試玩抓到 C2 口語「把門拉回來關好」和「不要跑出去」混用，前半段受後半段的安全保護攔截。試玩後補了獨立關門句的口語比對。混合句仍會要求釐清，以保留整句的否定保護。也針對 C1、B4 的樓梯與開窗提問補上可追溯問答。逐字紀錄保留當時畫面，這三項補強另由回歸測試驗證。

## 試玩後補測

使用完成補強後的教練再跑五回合，增加 4 次 API 呼叫。加上三場試玩，本階段實際呼叫 **60 次**。兩個提問由帶來源的劇本問答回答，不需要模型呼叫。五回合都沒有理解或敘事退回。

| 輸入 | 結果 |
| --- | --- |
| 那我把門拉回來關好 | GPT 提議 `close`，驗證通過，進入通報。 |
| 現在外面有煙可以走樓梯嗎？ | 小岑回答通往樓梯的走廊有濃煙，附 `safety`、`nfa`。 |
| 窗戶那邊有煙嗎，可以開窗嗎？ | 小岑說明開窗需要窗外無煙、先隔煙，附 `nfa`、`window-guide`。 |

## 切換原因

- 舊版的縮時重現用 95 ms 共用期限，理解與敘事各需 60 ms。結果是 `offline=false`、敘事 `TURN_TIMEOUT`、節點已從關門進到通報。共用期限能截斷敘事，無法單靠這個證據解釋使用者當時看到的離線標示。舊場次缺乏足以分辨原因的紀錄。
- 現版理解期限 8 秒，敘事另有 15 秒。敘事逾時或驗證未通過使用模板，保留理解結果。理解失敗才改用規則，顯示原因。傳輸中斷時由客戶端從上次確認狀態繼續處理，之後嘗試以原請求 ID 對帳並恢復，不直接覆寫已完成的本機進度。
- 回歸測試用可控制期限重現跨過舊共用期限、理解逾時、下回合恢復，以及 Chrome 的本機連線中斷與續玩。試玩沒有量到第二階段逾時。
