## 回退原因和提示

此表列出目前會寫入 `fallbackReason` 的原因。敘事第二階段另寫 `narrationFallbackReason`。

| 原因 | 顯示離線提示 | 說明 |
| --- | --- | --- |
| `TURN_TIMEOUT`、`MODEL_TIMEOUT` | 是 | 這回合連線逾時，暫時改用離線判讀。 |
| `CLIENT_TRANSPORT` | 是 | 這回合連線中斷或逾時，暫時改用離線判讀。 |
| `CLIENT_API_ERROR`、`PROVIDER_ERROR`、`MODEL_UNAVAILABLE`、`MODEL_INCOMPLETE` | 是 | 線上服務這回合未完成請求，暫時改用離線判讀。 |
| `MODEL_PROTECTED_LANGUAGE`、`MODEL_EVIDENCE`、`MODEL_UNSAFE_EVIDENCE`、`MODEL_GUARD_FAILED`、`MODEL_ACTION_UNAVAILABLE`、`MODEL_ACTION_REJECTED`、`MODEL_CONFLICTS_WITH_LITERAL`、`MODEL_NO_ACTION`、`MODEL_TOO_MANY_ACTIONS`、`MODEL_INVALID` | 否 | 語氣、原文證據、節點、前置條件、動作衝突或回傳格式驗證，保留原因供研究。 |
| `CLIENT_SYNC` | 否 | 客戶端收到不同的場次狀態或請求衝突，使用規則保留當前進度。 |
| `NOT_CONFIGURED`、`CALL_LIMIT` | 否 | 本機設定缺失或本次啟動的本機呼叫額度耗盡。 |
| `null` | 否 | 沒有理解回退。敘事逾時或敘事檢查退回模板另外記錄，沒有離線提示。 |

## 切換原因

- 舊版的縮時重現用 95 ms 共用期限，理解與敘事各需 60 ms。結果是 `offline=false`、敘事 `TURN_TIMEOUT`、節點已從關門進到通報。共用期限能截斷敘事，無法單靠這個證據解釋使用者當時看到的離線標示。舊場次缺乏足以分辨原因的紀錄。
- 現版理解期限 8 秒，敘事另有 15 秒。敘事逾時或驗證未通過使用模板，保留理解結果。理解失敗才改用規則，顯示原因。傳輸中斷時由客戶端從上次確認狀態繼續處理，之後嘗試以原請求 ID 對帳並恢復，不直接覆寫已完成的本機進度。
- 回歸測試用可控制期限重現跨過舊共用期限、理解逾時、下回合恢復，以及 Chrome 的本機連線中斷與續玩。試玩沒有量到第二階段逾時。
