# 情境演練後續規格

## 步驟 1 · 判讀與情境後果

- **A 類，物理上可行但荒謬或高風險。** 只有劇本定義且有官方依據的危險行動才能由狀態機結算既定危險後果。未建模的物理行動由狀態機記為無效決策，套用當前節點已核准的時間或資源代價。劇本需補齊代表性荒謬危險動作及對應來源。
- **B 類，不可能的事；C 類，亂講或離題。** 敘事在情境內回應，例如同伴把注意力拉回現場。狀態機仍扣除一個決策機會、時間或資源。即使沒有新的可執行動作，也不提供無代價的重試。
- **通用「時間流逝／情境惡化」事件。** 活躍場次每筆被判為無效決策的輸入，由狀態機提交一次 `time_elapsed`，記錄觸發原因、變動前後和劇本來源。達到劇本門檻才觸發既定 `environment_change`。無資源可扣時仍須推進決策時間，門檻可進入已定義的待救或危險結果。相同請求 ID 重試只結算一次。觀察、正當提問、假設與否定是學習互動，維持步驟 0.5 的不執行語意；不得把它們誤歸為 B／C 類扣除代價。
- GPT 只提議動作或表達回饋。時間、資源、路線、結局與有效動作皆由狀態機提交。所有危險判定與教育建議需附對應官方來源；來源不足的句子要明說不確定。

## 步驟 2 · 敘事

- 每個回覆應引用本回合的關鍵片段，或直接解釋該片段的意圖與已驗證後果。
- 同劇本不同輸入要有對應內容，換引號裡的文字、同義詞或標點視為重複模板。官方用語、固定結局標籤與必要的安全表述可以穩定呈現，判斷多樣性時另行排除。
- 結果依引擎提供。使用者提到劇本未確認的路線、資源或救援時，敘事應說明哪個資訊仍未知。

## 步驟 5 · 評估

- **開發集**由工程端撰寫，供除錯、提示調整與回歸測試。步驟 0、0.5 的資料都屬開發證據。
- **盲驗收集**由使用者與組員獨立撰寫及保存。工程端不預覽內容、不按驗收題調整模型或規則。凍結程式、劇本、模型、提示與評分規準後，才由組員執行並保留版本與逐回合 log。正式報告只採盲驗收集的數字。
- 除判讀、狀態正確性、降級成功率與延遲，新增**回覆多樣性**及**回應原話**。多樣性逐劇本統計去除原話引用與固定安全標籤後的重複模板比例，另由人工複核語意是否雷同。回應原話由評分者確認回覆是否針對本輪的行動、問題或情緒給出有資料支持的回應。
- 日誌記錄模式、是否實際呼叫模型及呼叫階段、驗證結果、是否降級、回覆、狀態差異與耗時。只有兩次 GPT 都完成且回覆通過驗證的回合才能用來判斷敘事提示是否過於制式。
